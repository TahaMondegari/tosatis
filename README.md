# ترب‌یار · دستیار هوشمند خرید حضوری

دستیار ایجنتیک برای خرید حضوری از فروشگاه‌ها، پاساژها و مراکز خرید تهران، روی دیتاست ترب (۶٬۴۷۶ فروشگاه، ۲۲۵٬۹۰۳ محصول، ۳۳۱٬۵۰۶ پیشنهاد قیمت).
کاربر را از «نمی‌دانم چه مدلی بخرم» تا «جلوی در مغازه داخل پاساژ» همراهی می‌کند: انتخاب مدل، مقایسه محصول و فروشگاه، هماهنگی با فروشنده، مسیریابی، برنامه بازدید و نظرسنجی بعد از خرید.

---

## ۱. اجرا و تست، مرحله‌به‌مرحله

### پیش‌نیازها
| مورد | نسخه | توضیح |
|---|---|---|
| Node.js | **۲۴ یا بالاتر** | سرور TypeScript را مستقیم اجرا می‌کند و از SQLite داخلی Node استفاده می‌کند؛ هیچ ماژول native یا دیتابیس جداگانه‌ای لازم نیست. |
| npm | ۱۰+ | همراه Node نصب می‌شود. |
| کلید BoxAPI | اختیاری | بدون کلید، دستیار قاعده‌محور جایگزین کار می‌کند؛ با کلید، ایجنت هوش مصنوعی کامل فعال می‌شود. |

```bash
node -v    # باید v24.x یا بالاتر باشد
```

### مرحله ۱: دریافت پروژه و نصب وابستگی‌ها
```bash
cd torob-yar
npm install
npm --prefix web install
```

### مرحله ۲: ساخت دیتابیس از دیتاست ترب (حدود ۱۵ ثانیه)
فایل zip دیتاست چالش را دانلود و باز کنید:
<https://startech.s3.ir-central1.arvanstorage.ir/starcoach-dataset-v16-cap300-csv.zip>

پوشه‌ای که `shops.csv`، `products.csv` و `offers.csv` در آن است را به اسکریپت بدهید:
```bash
npm run build:db -- "مسیر/پوشه/torob-dataset" data/torob.db
```
پیش‌فرض این اسکریپت پوشه `_input/torob-dataset` است. در پایان، آماری مثل زیر چاپ می‌شود:
`shops: 6476, products: 225903, offers: 331506, installment: 266, in_mall: 4148 ...`

### مرحله ۳: تنظیمات (`.env`)
```bash
cp .env.example .env
```
فقط یک مقدار لازم است:
```ini
BOXAPI_API_KEY=کلید_BoxAPI_شما
```
بقیه مقادیر پیش‌فرض مناسب دارند (جدول کامل در [بخش ۶](#۶-تنظیمات-env)).

### مرحله ۴: ساخت و اجرا
```bash
npm run build      # ساخت رابط کاربری (web/dist)
npm start          # سرور روی http://localhost:3000
```
پیام `ترب‌یار on :3000 · AI on (gpt-6-luna)` یعنی همه‌چیز آماده است.
اگر `AI off (rule-based fallback)` دیدید، کلید BoxAPI تنظیم نشده و برنامه با دستیار قاعده‌محور کار می‌کند.

> **حالت توسعه (اختیاری):** در دو ترمینال `npm run dev:server` و `npm run dev:web` را اجرا کنید و `http://localhost:5173` را باز کنید.

### مرحله ۵: بررسی سلامت
```bash
curl http://localhost:3000/api/health
# {"ok":true,"ai":true,"model":"torob-yar","calls":{"enabled":false,"mock":false}}

npm run smoke      # ۴ سناریوی گفتگو را مستقیم روی API اجرا می‌کند
```

### اجرا با Docker (یک فرمان)
ایمیج، دیتاست رسمی را خودش دانلود می‌کند و دیتابیس را داخل build می‌سازد:
```bash
docker build -t torob-yar .
docker run -p 3000:3000 -e BOXAPI_API_KEY=... torob-yar
```

### دیپلوی روی لیارا
```bash
npm i -g @liara/cli
liara login
liara deploy --app torob-yar --port 3000
liara env set BOXAPI_API_KEY=... --app torob-yar
```
`liara.json` و `Dockerfile` آماده‌اند. پلن پیشنهادی حداقل ۱ گیگ رم است. فایل `.env` وارد ایمیج نمی‌شود.

## ۳. نگاشت به معیارهای داوری

### محصول: حل مسئله خرید حضوری (۴ گام چالش)
1. **کشف نیاز:** `find_categories` و `category_insights` سؤال‌ها را از داده واقعی می‌سازند (سایز، رنگ و برند از مشخصات؛ بودجه از صدک ۲۵، ۵۰ و ۷۵ قیمت‌های حضوری).
2. **پیدا کردن فروشگاه نزدیک:** فاصله واقعی از موقعیت کاربر، زمان رسیدن بر اساس روش رفت‌وآمد و ترافیک ساعت شلوغ تهران، و همه فروشگاه‌های دارای محصول.
3. **مقایسه فروشگاه‌ها:** امتیاز وزنی بر اساس اولویت‌هایی که کاربر با کشیدن مرتب می‌کند (قیمت، فاصله، باز بودن، تازگی قیمت، گارانتی، قسطی). امتیازدهی صدکی است تا یک قیمت پرت مقیاس را خراب نکند.
4. **ارتباط و پیگیری:** پیام آماده، تماس، پیامک و واتساپ، ثبت جواب فروشنده، «موجودی تأییدشده» و جایگزین‌یابی فوری.

افزوده‌ها:
- فیلتر خرید قسطی/اعتباری (اسنپ‌پی، دیجی‌پی، تارا، ازکی‌وام، ترب‌پی) و تفکیک پذیرنده حضوری ترب‌پی.
- «ارزان‌تر هست؟»، برنامه بازدید چندفروشگاهی، و یافتن واحد داخل پاساژ.
- نظرسنجی هوشمند بعد از خرید، که وقتی کاربر بعد از مراجعه احتمالی به برنامه برمی‌گردد پرسیده می‌شود.
- **تماس هوشمند با فروشنده (اختیاری):** با API پشتیار ([بخش ۷](#۷-تماس-هوشمند-با-فروشنده-پشتیار--اختیاری)).

### UX و تجربه کاربری
- موبایل‌محور و راست‌به‌چین، با صفحه ثابت شبیه اپ‌های چت (بدون پرش صفحه) و Bottom sheet با کشیدن برای بستن.
- کارت‌ها، فیلترها و دکمه‌ها کار را بدون تایپ جلو می‌برند. سؤال تک‌انتخابی با یک لمس ارسال می‌شود.
- انیمیشن‌های نرم (استریم کلمه‌به‌کلمه، کارت‌های سه‌بعدی، نقشه طرح‌واره متحرک)، لرزش لمسی، و احترام به `prefers-reduced-motion`.
- تم تیره و «روشن ترب»، متن درشت برای همه سنین، فونت وزیرمتن (self-host)، PWA، ورودی صوتی فارسی، و زبان انگلیسی.

### هوشمندی
- **چندعاملی:** یک روتر سریع هر پیام را به یکی از چهار متخصص می‌دهد: «مشاور انتخاب مدل»، «کارشناس فروشگاه‌ها»، «کارشناس قیمت» و «میزبان گفتگو». هر کدام دستورالعمل و ابزارهای مخصوص خودش را دارد.
- **۱۵ ابزار** با خروجی کارت UI (`server/tools.ts`).
- توجه به شرایط مراجعه: ساعت کاری لحظه‌ای به وقت تهران، تعطیلی جمعه، «تا X دقیقه دیگر می‌بندد»، و هشدار بسته بودن در زمان رسیدن.
- جایگزین‌یابی خودکار در حالت‌های بسته، ناموجود، بی‌جواب و دور.
- تشخیص کالای «طرح» یا قیمت مشکوک.
- لحن انسانی و صمیمی. ایجنت هرگز مدل پشتیبان را فاش نمی‌کند (پرامپت به‌اضافه فیلتر خروجی).

### دیتاست و شفافیت
- **قیمت ثبت‌شده ≠ موجودی تأییدشده:** قیمت همیشه با تاریخ ثبتش («قیمت ۵ ماه پیش ثبت شده») نشان داده می‌شود. موجودی فقط بعد از تأیید فروشنده «تأییدشده» است.
- اطلاعات ناموجود صریح گفته می‌شود: «ساعت کاری ثبت نشده»، «نوع پذیرش نامشخص».
- «دسته فعالیت به‌تنهایی نشانه موجود بودن محصول نیست»: مغازه‌هایی که فقط دسته فعالیت‌شان مرتبط است جدا و با برچسب «موجودی نامشخص» نمایش داده می‌شوند.
- استخراج پاساژ، طبقه و واحد از نشانی متنی (۴٬۱۴۸ فروشگاه) و ساعت کاری هفتگی (۴٬۴۷۳ فروشگاه).

### پیاده‌سازی فنی
| بخش | فناوری |
|---|---|
| داده | `scripts/build-db.ts`: تبدیل CSV به SQLite با FTS5، نرمال‌سازی فارسی (ی/ک، ارقام، نیم‌فاصله) و مترادف‌ها (کتونی↔کتانی، گوشی↔موبایل) |
| سرور | Node 24 با TypeScript بومی، `node:sqlite`، Hono و SSE (استریم متن و کارت‌ها) |
| AI | BoxAPI (سازگار با OpenAI) با tool-calling، `gpt-6-luna` و مدل جایگزین `gpt-5.4-mini`، retry با backoff و timeout. در صورت قطعی، fallback قاعده‌محور |
| وب | Vite، React 19، Tailwind 4، Motion و dnd-kit؛ حالت برنامه با Zustand در مرورگر کاربر ذخیره می‌شود |
| چندزبانه | دیکشنری فارسی→انگلیسی برای وب و سرور (`web/src/i18n/en.json`، `server/i18n/en.json`) و زبان هر درخواست با هدر `x-lang` |
| مقیاس‌پذیری | ستون `city` و `/api/coverage`، انتخابگر ۳۱ استان و حدود ۲۳۰ شهر که با اضافه شدن داده خودکار فعال می‌شوند، و ارائه‌دهنده نقشه قابل تعویض |
| برند | `web/src/brand.ts`: لوگو و wordmark قابل تعویض بدون تغییر کد |

## ۷. تماس هوشمند با فروشنده (پشتیار) · اختیاری
به‌صورت پیش‌فرض **خاموش** است و تا روشن نشود هیچ دکمه یا ابزاری از آن دیده نمی‌شود.

وقتی روشن باشد، دستیار صوتی پشتیار به فروشنده زنگ می‌زند و موجودی، قیمت امروز، ساعت کاری و شرایط قسطی را می‌پرسد. وضعیت تماس لحظه‌به‌لحظه در کارت دیده می‌شود: شماره‌گیری ← زنگ ← گفتگو ← نتیجه. خلاصه حرف فروشنده ثبت می‌شود، و اگر محصول نبود، جایگزین می‌آید.

**راه‌اندازی:**
1. در پنل پشتیار یک اپراتور و یک کلید API بسازید.
2. در «ابزارها و وب‌هوک‌ها» ابزار `report_shop_answer` را بسازید:
   - متد: POST
   - آدرس: `https://دامنه/api/poshtyar/webhook`
   - هدر: `X-Webhook-Token`
   - فیلدها: `request_id`، `available`، `price`، `hours`، `installment`، `notes`

   سپس ابزار را به اپراتور وصل کنید.
3. در `.env`:
```ini
POSHTYAR_ENABLED=true
POSHTYAR_API_KEY=...
POSHTYAR_OPERATOR_ID=...
POSHTYAR_WEBHOOK_TOKEN=...
POSHTYAR_TEST_PHONE=09xxxxxxxxx   # شماره‌های دیتاست ساختگی‌اند؛ برای تست همه تماس‌ها به این شماره می‌رود
```
